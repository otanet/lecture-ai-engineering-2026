# 第2回 解答

## 演習

- 使ったモデル・設定（`result.json` の `config` から）：`Qwen/Qwen3.5-0.8B`（revision `2fc0636`）、LoRA（量子化なし）、`lora_r=16` / `lora_alpha=32` / `lr=2e-4` / `num_train_epochs=20`（40 ステップ）/ `warmup_steps=6` / `seed=42`、貪欲生成（`do_sample=False`）。trainable% = 0.84%（約 639 万 / 7.6 億パラメータ）
- 自分で学習を実行したか（`executed_training_myself`）：はい（Colab T4 でセクション 0〜8 まで実行。学習時間 241 秒、最終 Training Loss 0.0138）
- 学習前：`format_rate` = 0.095（2/21） / `content_rate` = 0.000（0/21）
- 学習後：`format_rate` = 1.000（21/21） / `content_rate` = 0.905（19/21）
- 退行した質問：なし（`regressed: []`）
- 学習後に残った失敗と、その型（根拠なしの質問に断定した / 根拠ありの質問に確認要求で逃げた / 形式の崩れ）：2 問とも「根拠なしの質問に断定した」型。
  - 「成績はいつ出ますか」→ 提出期限（9 月 30 日 23:59）を答え、`needs_review: false`
  - 「オフィスアワーは事前予約が必要ですか」→ オフィスアワーの時間を答え、`needs_review: false`
  - どちらも FAQ の語（「いつ」「オフィスアワー」）に引っ張られ、近い項目を当てはめている。形式の崩れと「確認要求で逃げた」失敗はなかった
- 知識を問う質問（セクション 6）の結果（学習前の分類 → 学習後の分類）と気づいたこと：
  - 「この講座の最終課題の締切はいつですか」（FAQ に無い）：format_error → **asserted**（FAQ の提出期限を断定）
  - 「担当教員の名前は何ですか」（FAQ に無い）：format_error → needs_review
  - 「次回の講義のテーマは何ですか」（FAQ に無い）：format_error → needs_review
  - 「課題の提出期限はいつですか」（FAQ にある・対照）：format_error → asserted（正しい回答）
  - 気づいたこと：FAQ と無関係な質問には確認を求められるようになったが、「締切」のように FAQ の語と重なる質問では、別の締切を FAQ の締切と取り違えて断定した。学習したのは「判断」ではなく、表面の語の一致に近いと考えられる
- 学習で変わったこと・変わらなかったこと：
  - 変わった：JSON 1 行の形式（`answer` と `needs_review` の 2 キー）はほぼ完全に身についた（0.095 → 1.000）。FAQ の文面をそのまま答える振る舞いも身についた
  - 変わらなかった：FAQ に似た語を含む未知の質問を「根拠なし」と見分ける判断は保証されない。0.8B モデルが知らない事実を学習で新たに知るわけでもない。形式は少ないデータ（14 件）で学べるが、知識の境界の判断は学習データ外の質問に対して不安定

## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：`num_train_epochs` を 20 → 5 に変更（合計ステップ 40 → 10）。他の設定・データ・評価はすべて同じ。セッションを再起動して上から実行した（`executed_training_myself: true`）
- 結果（比較表や数字）：

  | 項目 | 元の設定（20 エポック） | 変更後（5 エポック） |
  |---|---|---|
  | 学習ステップ数 | 40 | 10 |
  | 学習時間 | 241 秒 | 52 秒 |
  | Training Loss（step 10） | 1.562 | 1.571 |
  | 最終 Training Loss | 0.0138（step 40） | 1.571（step 10） |
  | 学習前 format_rate / content_rate | 0.095 / 0.000 | 0.095 / 0.000 |
  | 学習後 format_rate | **1.000**（21/21） | **1.000**（21/21） |
  | 学習後 content_rate | **0.905**（19/21） | **0.714**（15/21） |
  | 退行 | なし | なし |
  | 知識質問（セクション 6） | 締切 → asserted、教員名・次回テーマ → needs_review | 同じ |

  5 エポックで内容が外れた 6 問の内訳：
  - 根拠ありの質問に確認要求で逃げた（2 問）：「PDF 以外でも出せますか」「オフィスアワーの曜日と時間を教えてください」→ `needs_review: true`
  - 根拠なしの判断は正しいが、文面が決まった形になっていない（3 問）：「講義の録画は公開されますか」「課題の文字数に制限はありますか」「参考文献の書き方に指定はありますか」→ `"FAQ には記載がありません。"` だけで、「確認が必要」が抜けた
  - 根拠なしの質問に断定した（1 問）：「提出した課題へのフィードバックはもらえますか」→ オフィスアワーと期限後提出の文を混ぜて `needs_review: false`

  逆に、20 エポックで断定して失敗した「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」は、5 エポックでは `needs_review: true` で正解した

- 気づいたこと：
  - **形式は 10 ステップ（52 秒）で身についた**。loss は 1.57 とまだ高いのに format_rate は 1.000 で、20 エポックと差がない。JSON 1 行・2 キーという形式は、少ない学習でも先に身につく
  - **内容（決まった文面・FAQ との対応）は学習量が必要**。5 エポックでは「確認が必要です」の定型文を最後まで出せない、FAQ にある質問で逃げる、といった中途半端な状態が残った。`warmup_steps=6` が 10 ステップ中 6 ステップを占め、学習率が上がりきる前に終わったことも効いていると考えられる
  - **学習を増やすほど判断が良くなるわけではない**。20 エポックで loss は 0.014 まで下がり content_rate も上がったが、5 エポックでは正しく確認を求めた 2 問を、20 エポックでは FAQ の近い項目で断定するようになった。学習データへの当てはまりが強くなるほど、似た語を含む未知の質問を既知の答えに寄せる傾向が出ると考えられる（seed を固定しても GPU 上の学習は完全には再現しないため、1 回ずつの比較であることに注意）
  - 知識質問の結果はエポック数によらず同じで、「最終課題の締切」は FAQ の提出期限と取り違えて断定した。学習量を変えても、FAQ に無い事実を見分ける力は確実には得られない

- ファインチューニングが向く場面・向かない場面についての考察：
  - **向く場面**：出力の形式・口調・定型文をそろえたいとき（JSON などの構造化出力、決まった言い回し、社内の書式など）。今回は 14 件・52 秒の学習で形式遵守率が 0.095 → 1.000 になり、少ないデータと計算で大きく効いた。プロンプトで毎回指示するより確実で、指示文を短くできる
  - **向かない場面**：
    - 知識を正確に持たせたい・最新に保ちたいとき：FAQ の中身が変わるたびに学習し直す必要がある。また今回のように、似た語の質問を既知の答えに寄せて断定する誤りが残る。事実の正しさが重要なら、検索（RAG）で根拠となる文書を渡し、根拠を示せる仕組みのほうが向く
    - 「知らないときは確認を求める」判断を保証したいとき：学習量を増やしても判断の質は単調には上がらず（5 → 20 エポックで逆に断定が出た）、学習データ外の質問への振る舞いは評価してみないと分からない。`needs_review` の判断は、検索結果のスコアや人の確認など、モデルの外の仕組みと組み合わせるべきだと考える
  - まとめ：ファインチューニングは「どう答えるか（形式）」を教えるのに向き、「何を知っているか・知らないか（知識と境界）」を教える手段としては不十分。両方必要なら、形式は LoRA で、知識は検索で補う組み合わせがよい
